## MODIFIED Requirements

### Requirement: 工作区代码变更摘要应反映聚合后的总数

系统 SHALL 在任务列表和代码变更摘要中展示多仓库聚合后的总文件数、增删行统计；当工作区摘要计算过慢或失败时，系统仍必须优先保证主运行链路可用，并以降级摘要响应任务列表请求。

#### Scenario: 首页展示工作区变更规模

- **GIVEN** 当前任务绑定的工作目录下有多个 Git 仓库发生改动
- **WHEN** 首页或任务列表请求工作区变更摘要
- **THEN** 返回的 `fileCount`、`additions`、`deletions` 应为所有纳入仓库的汇总值

#### Scenario: 工作区摘要计算过慢

- **GIVEN** 某个工作区的仓库扫描或 Git 状态计算超过任务列表摘要接口的容忍时间
- **WHEN** 任务列表请求该工作区的 Diff 摘要
- **THEN** 系统必须返回降级后的摘要结果而不是长时间阻塞请求
- **AND** 该慢请求不得阻塞 Runner 状态上报等正常链路

#### Scenario: 工作区摘要计算失败

- **GIVEN** 某个工作区摘要计算因 Git 命令失败或子进程异常而无法完成
- **WHEN** 任务列表请求该工作区的 Diff 摘要
- **THEN** 系统必须返回可兼容的空摘要结果
- **AND** 任务列表接口仍应保持可用
